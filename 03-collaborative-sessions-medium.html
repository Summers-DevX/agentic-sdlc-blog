Collaborative Agentic Sessions

Synchronous, real-time collaboration where humans and agents build together, at machine speed.

by London Summers

7 min read

The SDLC breaks at agentic speed because coordination fails. Tickets become stale. 1000 PRs per week pile up with no review possible. There's no shared space where the team can see what's being built and course correct in real-time.

You need a completely different model, one where planning, context-gathering, decision-making, and development happen simultaneously, in one place, with everyone watching the same code materialise.

That model is collaborative agentic sessions.

From Separate Phases to Continuous Collaboration

Traditional SDLC separates concerns, Plan → Build → Review → Test → Deploy. Agents obliterate that timeline. The phases merge into simultaneity. Decisions emerge as code materializes, not before it. The only way to prevent divergence at agentic speed is to collapse the communication gaps. Planning, context-gathering, decision-making, and development must happen together, in one space, in real-time.

The Concrete Workflow

A PM describes a feature. A designer sketches the user flow in real-time, sharing their screen. Questions emerge, they discuss, they align on the design. A developer asks an architectural question. An architect agent jumps in with options. They discuss tradeoffs, decide.

An implementation agent starts building, visible to the whole team in real time. It writes code, runs tests, asks questions in the chat when it hits ambiguity. The PM notices something the agent missed, points it out. The agent course corrects immediately. A designer checks the UI, they update the code live together.

Within hours, the feature is built, validated, and aligned. No need to review PRs, the review has been happening all along.

What CAS Provides

1. Real-Time Code Visibility

File edits appear instantly in the chat. Everyone connected sees them. A designer watches UI components render. An architect sees database schema changes. Visibility kills ambiguity.

2. Synchronous Multi-Team Collaboration

Multiple team members in the same session via WebSockets. When the agent asks a question, the PM, architect, and designer see it simultaneously and respond immediately. Decisions happen in real-time, not over async rounds of feedback.

3. Session-Scoped Git Branches

Each session gets its own git branch with full CI/CD access. Tests run in real-time. Build output appears live. If something fails, the team sees it instantly. No hidden commits to main.

4. Live Tool Visibility

Git operations, shell commands, and file edits are all visible to every team member. When the agent runs tests, everyone sees the output. No "wait, what did the agent just do?"

5. Encrypted Integration

GitHub, Jira, Confluence, Anthropic integrations all stored securely. Security without friction.

How This Solves the Consensus Problem

Velocity without fragmentation, When everyone sees the same code materialising in real-time, cracks in understanding surface immediately. Conflicts are resolved in minutes, not discovered in production a month later.

Context for agents, Agents have access to the entire conversation. Requirements, design, architectural decisions, reasoning. They're building within a shared mental model, not in isolation.

Reduced cognitive load for humans, Humans aren't reviewing 1000 PRs. They're having a continuous conversation with agents about a feature being built. It's collaborative, not batch review.

The Three Macro-Priorities

1. Economic Sustainability

Intelligent model routing ensures teams aren't burning budget on the wrong tools. Real-time cost monitoring, dynamic model selection, and user-configurable budgets make agentic development economically viable at scale. Without this, teams overspend on high-capability models for routine tasks.

2. Omnipresent Collaboration

Agents work on your devices, in your spaces, at your pace. Native iOS/Android apps with full parity to desktop. The pattern, collaboration happens wherever work happens, not just at a desk.

3. Real-Time Guardrails

Validation shifts from post-merge gates to live-development checks. Security scanning as code is written, not weeks later. Performance budgeting that prevents regressions before they're committed. Specialised agents (security, performance, architecture) work in parallel, each contributing to decisions as they emerge.

What Needs to Change

Current tools won't work. Everything needs to be rewritten from scratch,

  • Git branching - Branches become sessions, not isolation mechanisms
  • Communication channels - Slack threads are too ephemeral. Conversations need to be tied to code and decisions
  • Change validation - PRs are retrospective. Validation happens during development, not after
  • Deployment models - Code is deployed as it's validated, not batched into releases

The Future

The SDLC didn't evolve to handle agent-generated code flowing at machine speed. It broke. The fix is synchronous, real-time, multi-role collaboration where everyone sees what's being built, everyone contributes to decisions, and alignment happens continuously, not retrospectively.

CAS proves it's possible. The question now is, will your organisation build it, or will you optimise a dead paradigm while your competitors operate at machine speed?
